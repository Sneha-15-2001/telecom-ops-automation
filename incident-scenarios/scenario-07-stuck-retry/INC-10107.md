# INC-10107 — Order parked in RETRYING, never revalidated

- **Status:** Open (P3)
- **Reported:** ops dashboard — "order sitting in RETRYING for hours"
- **Symptom:** order failed a short payment, was retried, then nothing —
  `RETRYING` with no subsequent `VALIDATING` event.
- **Suspected area:** retry executed but the follow-up validation never triggered
  (manual step missed / callback lost).

## 🧑‍💼 What the reporter says

Yesterday the customer underpaid by accident (₹1 against ₹59,999 — a test
tap), so payment validation failed the order. Ops correctly pressed retry,
moving it to `RETRYING` — and then the shift changed. The retry only *parks*
the order for revalidation; the revalidation itself is a separate manual step
that the next shift didn't know about. The order has sat in `RETRYING` ever
since: not failed, not moving, invisible to every queue except a status filter.

## 🔧 Engineering notes

### Timeline recovered from the system

1. `ORDER_CREATED → VALIDATED → PAYMENT_PENDING`
2. `PAYMENT_RECORDED` (₹1.00) → `PAYMENT_VALIDATED valid=false` → `ORDER_FAILED`
3. `STATUS_CHANGED FAILED → RETRYING` — ops retried
4. **Silence** — no `VALIDATING`/`VALIDATED` ever followed
