# INC-10113 — Number already belongs to another customer

- **Status:** Open (P2)
- **Reported:** store agent — "system won't give this number to my customer, says in use"
- **Symptom:** adding a subscription with MSISDN `919000007771` to customer 2
  fails: `MSISDN already in use` — it belongs to customer 1's subscription.
- **Suspected area:** number recycling — released numbers not quarantined before
  resale, or agent reading a stale availability sheet.

## 🧑‍💼 What the reporter says

A customer walked in asking for a "lucky number" they saw on a poster. The
agent tried to assign it, and the system refused: already in use. The poster
list came from last month's available-numbers export — stale. Now the agent
and the customer are arguing about whether the number is really taken.

## 🔧 Engineering notes

### Timeline recovered from the system
1. Subscription created for customer 1 with the MSISDN (first call succeeds)
2. Same MSISDN for customer 2 → `400 MSISDN already in use`
3. `subscription.msisdn` has a UNIQUE constraint — the guardrail working as designed

### How to reproduce

```bash
bash incident-scenarios/scenario-13-dup-msisdn/setup.sh
```

### Evidence to collect

- Second call → 400 with the duplicate message
- DB: exactly one subscription row carries the MSISDN (no double-allocation —
  contrast with a real double-booking, where two rows would exist)
