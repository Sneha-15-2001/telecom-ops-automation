# INC-10112 — Fiber port reserved, broadband activation still failed

- **Status:** Open (P2)
- **Reported:** field team — "port is booked for the customer but broadband won't activate"
- **Symptom:** fiber port `RESERVED` for order 7777, yet the broadband request
  failed with `MISSING_RESOURCE`.
- **Suspected area:** provisioning request opened without the reserved port linked.

## 🧑‍💼 What the reporter says

The technician reserved the customer's fiber port in the morning and raised
the broadband activation in the afternoon — but typed the order through the
manual screen, which doesn't force-link the reservation. Activation failed
saying "no resource", while the port sits blocked under the customer's name.
The customer has a reserved port and no internet.

## 🔧 Engineering notes

### Timeline recovered from the system
1. `RESOURCE_RESERVED` — fiber port held for order 7777
2. `PROVISIONING_CREATED` — broadband request with `resourceNumber: null`
3. `PROVISIONING_FAILED` — `MISSING_RESOURCE`

### How to reproduce

```bash
bash incident-scenarios/scenario-12-fiber-noresource/setup.sh
```

### Evidence to collect

- `GET /api/provisioning/{id}` → FAILED, `resourceNumber` null
- `GET /api/inventory/available?type=FIBER_PORT` — the port missing (still RESERVED)
- Logs share one correlation ID across inventory + provisioning: reservation
  exists, activation never saw it
