# INC-10110 — Expired hold leaks: confirm refused forever, resource stuck RESERVED

- **Status:** Open (P2)
- **Reported:** inventory ops — "SIMs stuck RESERVED with dead holds, pool shrinking daily"
- **Symptom:** confirming a past-TTL hold fails with `Reservation expired`, yet the
  resource stays `RESERVED` — and the reservation itself stays `ACTIVE`, so every
  retry fails identically. A permanent leak: the unit can never be freed by API.
- **Suspected area:** `requireActive` marks the hold EXPIRED in memory but the
  thrown exception rolls the transaction back, so neither the EXPIRED marking
  nor any resource release is ever committed. No sweeper, no alert.

## 🧑‍💼 What the reporter says

A storefront reserved a SIM with a 1-minute hold while the customer hunted for
their ID proof. They returned after 3 minutes; confirm correctly refused the
stale hold (`Reservation expired`) — but the SIM stayed `RESERVED` against a
dead hold. Every such event permanently removes one unit from sellable stock.
Multiplied across stores, the SIM pool bled for weeks before the monitor caught
the RESERVED-but-no-ACTIVE-hold divergence.

## 🔧 Engineering notes

### Timeline recovered from the system

1. `RESOURCE_RESERVED` — SIM held, TTL 1 minute
2. TTL passes, no confirm/release
3. Late confirm → `400 Reservation expired`; the exception rolls back the
   transaction, so the hold stays `ACTIVE` and the resource stays `RESERVED`
4. **Silence** — every retry fails identically; stock leaks one unit per occurrence

### How to reproduce

```bash
bash incident-scenarios/scenario-10-expired-hold/setup.sh
# waits ~70s for the TTL to pass, then confirms into the leak
```

### Evidence to collect

- `POST …/reservations/{id}/confirm` → `400 Reservation expired` (repeatable forever)
- `GET /api/inventory/reservations/{id}` → still `ACTIVE` (rollback ate the marking)
- `GET /api/inventory/resources/{id}` → still `RESERVED` (should be AVAILABLE)
- History: `RESOURCE_RESERVED` with no `RESOURCE_RELEASED`
- Query the divergence any time: resources RESERVED whose holds all past TTL
