# INC-10111 — Corporate bulk order partially failed

- **Status:** Open (P2)
- **Reported:** enterprise sales — "2 of 3 employee connections went through, third vanished"
- **Symptom:** bulk response shows 2× `success: true`, 1× `success: false`
  (`customerId: must not be null; items: must not be empty`).

## 🧑‍💼 What the reporter says

HR sent a 3-employee joining kit as one bulk order yesterday. Two connections
activated fine; the third never became an order at all — no order number, no
status to track, just an error line buried in the bulk response. HR insists
all three rows were filled in the spreadsheet.

## 🔧 Engineering notes

### Timeline recovered from the system
1. `BULK_ITEM_*` per item — 2 created, 1 rejected at validation
2. No order row exists for the bad item (rejected pre-create, by design)

### How to reproduce

```bash
bash incident-scenarios/scenario-11-bulk-partial/setup.sh
```

### Evidence to collect

- Bulk response: per-item `success`/`error` flags (not HTTP 400 — HTTP 200 by design)
- Logs (`scripts/search-logs.sh <correlationId>`): `BULK_ITEM_REJECTED` with the cause
- DB: only 2 new `telecom_order` rows
