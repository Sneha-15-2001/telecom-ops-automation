# INC-10122 — HTTP 415 and 405: malformed integration calls

- **Status:** Open (P3)
- **Reported:** a partner integration
- **Symptom:** `415 UNSUPPORTED_MEDIA_TYPE` and `405 METHOD_NOT_ALLOWED`.
- **Suspected area:** none — the client is sending the wrong request.

## 🧑‍💼 What the reporter says

"Our order submission started failing. We are sending JSON, we are sure of it.
It works from Postman."

## 🔧 Engineering notes

### The usual cause

They are sending a JSON body with `Content-Type: text/plain`. Postman sets the
header for you, which is why it works there. The server refuses to guess the
format — treating `text/plain` as JSON would make "guessing" the API contract.

Both failures used to return **500**, which told the partner our server had
crashed. They are now 415 and 405, which point at their request.

### Why this mattered

Before this change, a bad `Content-Type` fell through to the catch-all handler
and surfaced as `INTERNAL_ERROR` — the caller reasonably concluded the fault was
ours and spent hours investigating our logs. A misconfigured integration should
never be able to make the vendor look broken.

### How to reproduce

```bash
bash incident-scenarios/scenario-22-media-type-415/setup.sh
```

### Resolution

Ask the partner to send `Content-Type: application/json`. No server change
required.
