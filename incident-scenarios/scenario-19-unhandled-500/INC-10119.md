# INC-10119 — HTTP 500 Internal Server Error: unhandled exception

- **Status:** Open (P1)
- **Reported:** storefront
- **Symptom:** 500 `INTERNAL_ERROR` with no useful detail in the body.
- **Suspected area:** a code path nothing maps to a specific error.

## 🧑‍💼 What the reporter says

"We get a 500 and a blank error. We cannot tell what went wrong or give the
customer anything useful. Please make the error message better."

## 🔧 Engineering notes

### The error body is deliberately unhelpful — and that is correct

A 500 body says:

> Unexpected error. Quote correlation ID `34a7b23d-…` when reporting this.

It carries **no stack trace, no class names, no SQL**. Returning internals to a
caller leaks schema and infrastructure detail to anyone who can provoke an
error. The full exception is written to the log *with the same correlation ID*,
so support can go from the customer's screenshot to the stack trace in one grep.

### The actual fix is upstream

The handler is the last line of defence; anything reaching it is an unmapped
exception. This order trips on an extreme quantity. The real work is either
validating the range earlier and returning 400, or mapping the specific
arithmetic failure. Tightening the global handler only changes the wording of a
bug that still exists.

### How to reproduce

```bash
bash incident-scenarios/scenario-19-unhandled-500/setup.sh
grep UNHANDLED_EXCEPTION logs/order-service/app.log     # full stack trace
```

### Related

If 500s appear in clusters with the same correlation ID prefix, they are one
incident, not many.
